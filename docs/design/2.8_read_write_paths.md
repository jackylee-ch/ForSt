## 1. 设计目标与约束

### 1.1 设计目标

读写路径是 LSM-Tree 引擎最核心的数据通路，直接决定引擎的延迟和吞吐性能。ForSt-RS 的读写路径设计需要在 Arrow-native 存储层列式数据模型下实现以下目标：

1. **Arrow-native 存储全链路**：从写入到存储到读取，数据始终以 Arrow RecordBatch 为单元，消除逐条 byte[] 序列化/反序列化（文档 1.7 瓶颈 B2）
2. **批量化操作**：get/put 均支持批量模式（batch_get/batch_write），减少 Java-Rust 跨语言调用次数（文档 1.7 B1，每次 JNI 调用 57ns）
3. **MVCC 多版本可见性**：基于 sequence number 的快照隔离，读取不阻塞写入
4. **低锁竞争写入**：消除 ForSt/RocksDB 的 WriteThread mutex + DB mutex 竞争（文档 1.7 B4）
5. **三级缓存加速读取**：集成 Block Cache（文档 2.4）实现热数据快速返回，消除 B3 缓存未命中
6. **MergeOperator 支持**：读路径中在线合并 Merge 记录（ListState append 语义，文档 2.3）

### 1.2 已知约束

| 约束 ID | 来源 | 内容 |
|---------|------|------|
| C1 | 文档 1.16 | 元数据采用模式 B（纯 Checkpoint），VersionSet 纯内存管理 |
| C3 | 文档 1.9 | Arrow RecordBatch 可在 Java/Rust 间零拷贝传输 |
| C4 | 文档 1.14 | ForSt-RS 不管 Schema Evolution，透传 opaque bytes |
| C11 | 文档 2.2 | SST DataBlock 格式为 Arrow RecordBatch（key/value/sequence/op_type 4 列） |
| C12 | 文档 2.3 | MemTable 内部使用与 SST 一致的列式布局 |
| C13 | 文档 2.4 | L1 Cache 缓存解码后的 Arrow RecordBatch |

### 1.3 与 ForSt/RocksDB 的读写路径对比

| 维度 | ForSt/RocksDB | ForSt-RS | 改进点 |
|------|--------------|----------|--------|
| **数据单元** | Slice (byte[]) 逐条 | Arrow RecordBatch 批量列式 | 消除 B2 双重序列化 |
| **写入模型** | WriteThread 状态机 + DB mutex | 无锁写入队列 + 批量提交 | 消除 B4 锁竞争 |
| **读取模型** | Get → MemTable → L0 → L1..Ln (逐条) | batch_get → MemTable → L0 → Ln (批量) | 减少函数调用 |
| **版本管理** | SuperVersion (MemTable + Imm + Current Version) | 类似概念：SnapshotView | 语义一致 |
| **Merge 执行** | MergeHelper (读路径在线合并) | MergeOperator trait (Arrow 批量合并) | 减少 merge 次数 |
| **缓存交互** | LRU Cache lookup per block | ShardedClock 无锁 lookup per block | 消除 B7 锁争用 |
| **跨语言传输** | JNI byte[] 拷贝 | Arrow C Data Interface 零拷贝 | 消除 B1 拷贝 |

## 2. 写路径设计

### 2.1 写入操作总览

ForSt-RS 支持四种写入操作：

| 操作 | 语义 | OpType | 使用场景 |
|------|------|--------|---------|
| Put | 覆盖写入 key=value | 1 | ValueState, MapState |
| Delete | 删除 key | 2 | ValueState.clear(), MapState.remove() |
| Merge | 追加合并 | 3 | ListState.add() |
| batch_write | 批量写入 WriteBatch | 混合 | asyncExecute 批量提交 |

### 2.2 单条写入路径

```rust
/// 单条 Put 写入路径
pub fn put(&self, cf: &ColumnFamilyHandle, key: &[u8], value: &[u8]) -> Result<()> {
    // Step 1: 分配全局递增序列号
    let seq = self.sequence_number.fetch_add(1, Ordering::SeqCst);

    // Step 2: 检查写入速率控制（WriteController）
    //   - 如果 L0 文件数接近限制 → sleep（back pressure）
    //   - 如果 MemTable 数量过多 → stall
    self.write_controller.may_throttle()?;

    // Step 3: 插入到 ColumnFamily 的 Active MemTable
    let cf_data = self.get_cf(cf)?;
    cf_data.memtable.insert(key, value, seq, OpType::Put)?;

    // Step 4: 检查是否需要切换 MemTable
    if cf_data.memtable.approximate_memory_usage() >= self.options.write_buffer_size {
        self.maybe_switch_memtable(cf)?;
    }

    Ok(())
}
```

### 2.3 批量写入路径（WriteBatch）

批量写入是 ForSt-RS 的核心优化点，面向 Flink asyncExecute 的批量提交模式。

```rust
/// WriteBatch: 批量写入描述
pub struct WriteBatch {
    entries: Vec<WriteBatchEntry>,
}

pub struct WriteBatchEntry {
    pub cf: ColumnFamilyHandle,
    pub key: Vec<u8>,
    pub value: Option<Vec<u8>>,  // None for Delete
    pub op_type: OpType,
}

/// 批量写入路径
pub fn batch_write(&self, batch: WriteBatch) -> Result<()> {
    // Step 1: 分配连续序列号范围
    let count = batch.entries.len() as u64;
    let first_seq = self.sequence_number.fetch_add(count, Ordering::SeqCst);

    // Step 2: 写入速率控制
    self.write_controller.may_throttle()?;

    // Step 3: 按 ColumnFamily 分组
    let grouped = batch.group_by_cf();

    // Step 4: 批量插入到各 CF 的 MemTable
    let mut seq = first_seq;
    for (cf_id, entries) in grouped {
        let cf_data = self.get_cf_by_id(cf_id)?;

        // 构建 Arrow RecordBatch 进行批量插入
        let record_batch = build_record_batch(&entries, seq)?;
        cf_data.memtable.batch_insert(&record_batch)?;

        seq += entries.len() as u64;
    }

    // Step 5: 检查所有 CF 是否需要切换 MemTable
    for (cf_id, _) in grouped {
        let cf_data = self.get_cf_by_id(cf_id)?;
        if cf_data.memtable.approximate_memory_usage() >= self.options.write_buffer_size {
            self.maybe_switch_memtable_by_id(cf_id)?;
        }
    }

    Ok(())
}

/// 构建写入用的 Arrow RecordBatch
fn build_record_batch(entries: &[WriteBatchEntry], first_seq: u64) -> Result<RecordBatch> {
    let n = entries.len();
    let mut key_builder = BinaryBuilder::with_capacity(n, n * 64);
    let mut value_builder = BinaryBuilder::with_capacity(n, n * 256);
    let mut seq_builder = UInt64Builder::with_capacity(n);
    let mut op_builder = UInt8Builder::with_capacity(n);

    for (i, entry) in entries.iter().enumerate() {
        key_builder.append_value(&entry.key);
        match &entry.value {
            Some(v) => value_builder.append_value(v),
            None => value_builder.append_null(),
        }
        seq_builder.append_value(first_seq + i as u64);
        op_builder.append_value(entry.op_type as u8);
    }

    RecordBatch::try_new(
        SST_SCHEMA.clone(),  // key: Binary, value: Binary, sequence: UInt64, op_type: UInt8
        vec![
            Arc::new(key_builder.finish()),
            Arc::new(value_builder.finish()),
            Arc::new(seq_builder.finish()),
            Arc::new(op_builder.finish()),
        ],
    )
}
```

### 2.4 MemTable 切换与 Flush 触发

```rust
/// MemTable 切换逻辑
fn maybe_switch_memtable(&self, cf: &ColumnFamilyHandle) -> Result<()> {
    let cf_data = self.get_cf(cf)?;
    let usage = cf_data.memtable.approximate_memory_usage();

    if usage < self.options.write_buffer_size {
        return Ok(());
    }

    // Step 1: 冻结当前 MemTable → ImmutableMemTable
    let frozen = cf_data.swap_active_memtable()?;
    cf_data.imm_list.push(frozen);

    // Step 2: 更新 VersionSet（纯内存操作，无 fsync — 约束 C2）
    // 不需要 LogAndApply，只需更新 SuperVersion 引用

    // Step 3: 检查 Immutable MemTable 数量
    if cf_data.imm_list.len() >= self.options.max_write_buffer_number {
        // stall 写入直到至少一个 Immutable 被 flush
        self.write_controller.set_stall(true);
    }

    // Step 4: 通知后台 Flush 线程
    self.flush_scheduler.schedule_flush(cf.clone());

    Ok(())
}
```

### 2.5 WriteController（写入速率控制）

ForSt-RS 的 WriteController 比 ForSt/RocksDB 更简洁（无 WriteThread 状态机）：

```rust
/// 写入速率控制器
/// 解决 B4（写路径锁竞争）：无锁设计，使用原子变量
pub struct WriteController {
    /// L0 文件数告警阈值（接近触发 Compaction）
    l0_slowdown_trigger: u32,
    /// L0 文件数停止写入阈值
    l0_stop_trigger: u32,
    /// 当前 stall 状态
    stalled: AtomicBool,
    /// stall 唤醒通知
    stall_condvar: Condvar,
    stall_mutex: Mutex<()>,
}

impl WriteController {
    pub fn may_throttle(&self) -> Result<()> {
        // 检查是否需要 stall
        if self.stalled.load(Ordering::Acquire) {
            let lock = self.stall_mutex.lock();
            while self.stalled.load(Ordering::Acquire) {
                self.stall_condvar.wait(&lock);
            }
        }
        Ok(())
    }

    /// Flush 完成后解除 stall
    pub fn on_flush_complete(&self) {
        if self.stalled.swap(false, Ordering::Release) {
            self.stall_condvar.notify_all();
        }
    }
}
```

## 3. 读路径设计

### 3.1 读取操作总览

ForSt-RS 支持四种读取操作：

| 操作 | 语义 | 使用场景 |
|------|------|---------|
| get(key) | 单点精确查找 | ValueState.value(), MapState.get() |
| batch_get(keys) | 批量点查 | asyncExecute 批量读取 |

| prefix_scan(prefix) | 前缀扫描 | Delta Join prefix lookup |

### 3.2 单点读取路径（Get）

```rust
/// 单点读取路径 — LSM-Tree 经典多层查找
pub fn get(&self, cf: &ColumnFamilyHandle, key: &[u8]) -> Result<Option<Vec<u8>>> {
    let cf_data = self.get_cf(cf)?;

    // Step 0: 获取当前 SnapshotView（类似 SuperVersion）
    // 包含：Active MemTable + ImmutableMemTable 列表 + Current Version (SST 布局)
    let snapshot = cf_data.snapshot_view();
    let read_seq = self.sequence_number.load(Ordering::Acquire);

    // === 阶段 1: 查找 Active MemTable ===
    if let Some(entry) = snapshot.active_memtable.get(key, read_seq)? {
        return self.resolve_entry(entry, key, cf, read_seq);
    }

    // === 阶段 2: 查找 Immutable MemTable 列表（从新到旧）===
    for imm in snapshot.imm_list.iter().rev() {
        if let Some(entry) = imm.get(key, read_seq)? {
            return self.resolve_entry(entry, key, cf, read_seq);
        }
    }

    // === 阶段 3: 查找 SST 文件（L0 → L1 → ... → Ln）===
    let version = snapshot.current_version();

    // L0: 可能有多个重叠 SST，需全部检查（从新到旧）
    for sst in version.l0_files().iter().rev() {
        if let Some(entry) = self.search_sst(sst, key, read_seq)? {
            return self.resolve_entry(entry, key, cf, read_seq);
        }
    }

    // L1-Ln: 每层最多一个 SST 包含目标 key（层内有序不重叠）
    for level in 1..version.num_levels() {
        if let Some(sst) = version.find_sst_for_key(level, key) {
            if let Some(entry) = self.search_sst(sst, key, read_seq)? {
                return self.resolve_entry(entry, key, cf, read_seq);
            }
        }
    }

    // 所有层都没找到
    Ok(None)
}

/// 在单个 SST 文件中查找 key
fn search_sst(
    &self,
    sst_meta: &SstFileMeta,
    key: &[u8],
    read_seq: u64,
) -> Result<Option<ValueEntry>> {
    // Step 1: min/max key 快速排除
    if key < sst_meta.smallest_key.as_slice() || key > sst_meta.largest_key.as_slice() {
        return Ok(None);
    }

    // Step 2: Bloom Filter 检查（SBBF，文档 2.2 §2.3）
    let bloom = self.load_bloom_filter(sst_meta)?;  // 从 Block Cache 或磁盘加载
    if !bloom.may_contain(key) {
        return Ok(None);  // 一定不存在
    }

    // Step 3: Sparse Index 二分查找定位 DataBlock
    let index = self.load_index(sst_meta)?;  // 从 Block Cache 或磁盘加载
    let block_offset = index.find_block_for_key(key)?;

    // Step 4: 加载 DataBlock（Arrow RecordBatch）
    let cache_key = CacheKey::new(sst_meta.file_number, block_offset);
    let data_block = match self.block_cache.lookup(&cache_key) {
        Some(entry) => entry,  // Cache 命中
        None => {
            // Cache 未命中 → 从磁盘读取 + 解码 + 插入缓存
            let raw = self.read_block_from_disk(sst_meta, block_offset)?;
            let decoded = decode_arrow_record_batch(&raw)?;
            let entry = CacheEntry::DecodedBatch(Arc::new(decoded));
            self.block_cache.insert(cache_key, entry.clone(), CachePriority::Low)?;
            entry
        }
    };

    // Step 5: 在 DataBlock (Arrow RecordBatch) 中二分查找
    search_key_in_record_batch(&data_block, key, read_seq)
}
```

### 3.3 DataBlock 内 Key 查找

SST DataBlock 是一个 Arrow RecordBatch，包含 4 列：key(Binary), value(Binary), sequence(UInt64), op_type(UInt8)。行按 (key ASC, sequence DESC) 排序。

```rust
/// 在 Arrow RecordBatch (DataBlock) 中查找 key
/// 利用 key 列有序的特性进行二分查找
fn search_key_in_record_batch(
    batch: &RecordBatch,
    target_key: &[u8],
    read_seq: u64,
) -> Result<Option<ValueEntry>> {
    let key_col = batch.column(0).as_any().downcast_ref::<BinaryArray>().unwrap();
    let value_col = batch.column(1).as_any().downcast_ref::<BinaryArray>().unwrap();
    let seq_col = batch.column(2).as_any().downcast_ref::<UInt64Array>().unwrap();
    let op_col = batch.column(3).as_any().downcast_ref::<UInt8Array>().unwrap();

    let n = batch.num_rows();

    // 二分查找第一个 key >= target_key 的位置
    let mut lo = 0usize;
    let mut hi = n;
    while lo < hi {
        let mid = lo + (hi - lo) / 2;
        if key_col.value(mid) < target_key {
            lo = mid + 1;
        } else {
            hi = mid;
        }
    }

    // 遍历所有 key == target_key 的行，找到 sequence <= read_seq 的最新版本
    let mut idx = lo;
    while idx < n && key_col.value(idx) == target_key {
        let seq = seq_col.value(idx);
        if seq <= read_seq {
            let op = OpType::from_u8(op_col.value(idx));
            return match op {
                OpType::Put => Ok(Some(ValueEntry::Value(value_col.value(idx).to_vec()))),
                OpType::Delete => Ok(Some(ValueEntry::Deleted)),
                OpType::Merge => Ok(Some(ValueEntry::Merge(value_col.value(idx).to_vec()))),
            };
        }
        idx += 1;
    }

    Ok(None)
}
```

### 3.4 批量读取路径（batch_get）

batch_get 是 ForSt-RS 的核心优化——将多个 key 的查找批量化，共享 SST 文件加载和 Bloom Filter 检查。

```rust
/// 批量读取路径
pub fn batch_get(
    &self,
    cf: &ColumnFamilyHandle,
    keys: &[&[u8]],
) -> Result<Vec<Option<Vec<u8>>>> {
    let cf_data = self.get_cf(cf)?;
    let snapshot = cf_data.snapshot_view();
    let read_seq = self.sequence_number.load(Ordering::Acquire);
    let n = keys.len();

    // 结果数组，初始化为 None
    let mut results: Vec<Option<ValueEntry>> = vec![None; n];
    // 未解决的 key 索引集合
    let mut pending: Vec<usize> = (0..n).collect();

    // === 阶段 1: 批量查找 Active MemTable ===
    let mut still_pending = Vec::new();
    for &idx in &pending {
        if let Some(entry) = snapshot.active_memtable.get(keys[idx], read_seq)? {
            results[idx] = Some(entry);
        } else {
            still_pending.push(idx);
        }
    }
    pending = still_pending;
    if pending.is_empty() { return self.resolve_results(results, keys, cf, read_seq); }

    // === 阶段 2: 批量查找 Immutable MemTable 列表 ===
    for imm in snapshot.imm_list.iter().rev() {
        let mut still_pending = Vec::new();
        for &idx in &pending {
            if let Some(entry) = imm.get(keys[idx], read_seq)? {
                results[idx] = Some(entry);
            } else {
                still_pending.push(idx);
            }
        }
        pending = still_pending;
        if pending.is_empty() { return self.resolve_results(results, keys, cf, read_seq); }
    }

    // === 阶段 3: 批量查找 SST 文件 ===
    let version = snapshot.current_version();

    // L0: 批量 Bloom Filter 过滤
    for sst in version.l0_files().iter().rev() {
        let bloom = self.load_bloom_filter(sst)?;

        // 批量 Bloom 检查：收集可能存在的 key
        let mut candidates: Vec<usize> = Vec::new();
        for &idx in &pending {
            if bloom.may_contain(keys[idx]) {
                candidates.push(idx);
            }
        }

        // 对通过 Bloom 检查的 key，批量加载 DataBlock 并查找
        if !candidates.is_empty() {
            self.batch_search_sst(sst, keys, &candidates, &mut results, read_seq)?;

            // 更新 pending：移除已找到的
            pending.retain(|idx| results[*idx].is_none());
        }

        if pending.is_empty() { return self.resolve_results(results, keys, cf, read_seq); }
    }

    // L1-Ln: 每层批量查找
    for level in 1..version.num_levels() {
        // 按 key 的 SST 归属分组
        let sst_groups = version.group_keys_by_sst(level, keys, &pending);

        for (sst, key_indices) in sst_groups {
            let bloom = self.load_bloom_filter(&sst)?;
            let candidates: Vec<usize> = key_indices.iter()
                .filter(|&&idx| bloom.may_contain(keys[idx]))
                .copied()
                .collect();

            if !candidates.is_empty() {
                self.batch_search_sst(&sst, keys, &candidates, &mut results, read_seq)?;
            }
        }

        pending.retain(|idx| results[*idx].is_none());
        if pending.is_empty() { break; }
    }

    self.resolve_results(results, keys, cf, read_seq)
}

/// 批量 SST 查找：对同一 SST 文件中的多个 key 一次性查找
fn batch_search_sst(
    &self,
    sst: &SstFileMeta,
    all_keys: &[&[u8]],
    indices: &[usize],
    results: &mut [Option<ValueEntry>],
    read_seq: u64,
) -> Result<()> {
    let index = self.load_index(sst)?;

    // 按 DataBlock 分组：避免重复加载同一 Block
    let mut block_groups: HashMap<u64, Vec<usize>> = HashMap::new();
    for &idx in indices {
        if let Some(block_offset) = index.find_block_for_key(all_keys[idx])? {
            block_groups.entry(block_offset).or_default().push(idx);
        }
    }

    // 每个 DataBlock 只加载一次，批量查找多个 key
    for (block_offset, key_indices) in block_groups {
        let cache_key = CacheKey::new(sst.file_number, block_offset);
        let data_block = self.load_or_cache_block(cache_key, sst, block_offset)?;

        for &idx in &key_indices {
            if let Some(entry) = search_key_in_record_batch(&data_block, all_keys[idx], read_seq)? {
                results[idx] = Some(entry);
            }
        }
    }

    Ok(())
}
```

### 3.5 Merge 记录在线合并

当读路径遇到 OpType::Merge 记录时，需要在线合并所有连续的 Merge 操作：

```rust
/// 解析单个 key 的查找结果
/// 处理 Merge 语义：收集所有 Merge 操作值，与 base value（Put/Delete）合并
fn resolve_entry(
    &self,
    first_entry: ValueEntry,
    key: &[u8],
    cf: &ColumnFamilyHandle,
    read_seq: u64,
) -> Result<Option<Vec<u8>>> {
    match first_entry {
        ValueEntry::Value(v) => Ok(Some(v)),
        ValueEntry::Deleted => Ok(None),
        ValueEntry::Merge(merge_value) => {
            // 需要继续向下层查找，收集所有 Merge 操作和最终的 base value
            let mut merge_operands = vec![merge_value];
            let base_value = self.collect_merge_operands(
                key, cf, read_seq, &mut merge_operands
            )?;

            // 调用 MergeOperator 合并
            let cf_data = self.get_cf(cf)?;
            if let Some(ref merge_op) = cf_data.options.merge_operator {
                let result = merge_op.full_merge(
                    key,
                    base_value.as_deref(),
                    &merge_operands,
                )?;
                Ok(Some(result))
            } else {
                Err(Error::NoMergeOperator)
            }
        }
    }
}

/// 收集所有 Merge 操作值直到遇到 Put 或 Delete
fn collect_merge_operands(
    &self,
    key: &[u8],
    cf: &ColumnFamilyHandle,
    read_seq: u64,
    operands: &mut Vec<Vec<u8>>,
) -> Result<Option<Vec<u8>>> {
    // 继续向更深层查找，收集 Merge 操作
    // 遇到 Put → 返回 Put value 作为 base
    // 遇到 Delete → 返回 None 作为 base（相当于从空开始合并）
    // 到达底层无更多记录 → 返回 None（partial merge）

    let cf_data = self.get_cf(cf)?;
    let snapshot = cf_data.snapshot_view();
    let version = snapshot.current_version();

    // 搜索更深层的 SST 文件（跳过已搜索的层）
    for level in 0..version.num_levels() {
        let sst_files = if level == 0 {
            version.l0_files().to_vec()
        } else {
            version.find_sst_for_key(level, key)
                .map(|s| vec![s])
                .unwrap_or_default()
        };

        for sst in sst_files.iter().rev() {
            if let Some(entry) = self.search_sst(sst, key, read_seq)? {
                match entry {
                    ValueEntry::Value(v) => return Ok(Some(v)),
                    ValueEntry::Deleted => return Ok(None),
                    ValueEntry::Merge(v) => operands.push(v),
                }
            }
        }
    }

    Ok(None)  // No base value found
}
```

### 3.6 MergeOperator 接口

```rust
/// Merge 操作符接口（等价于 RocksDB MergeOperator）
/// Flink ListState 使用 StringAppendOperator 语义
pub trait MergeOperator: Send + Sync {
    /// 完整合并：base_value + 所有 operands
    /// base_value = None 表示 key 之前不存在或被删除
    fn full_merge(
        &self,
        key: &[u8],
        base_value: Option<&[u8]>,
        operands: &[Vec<u8>],
    ) -> Result<Vec<u8>>;

    /// 部分合并：合并两个 operand（用于 Compaction 中的提前合并）
    fn partial_merge(
        &self,
        key: &[u8],
        left: &[u8],
        right: &[u8],
    ) -> Result<Vec<u8>>;
}

/// Flink ListState 的 Merge 操作符实现
/// 语义：用分隔符连接所有值（等价于 StringAppendOperator）
pub struct ListAppendMergeOperator {
    delimiter: u8,  // 默认 ','
}

impl MergeOperator for ListAppendMergeOperator {
    fn full_merge(
        &self,
        _key: &[u8],
        base_value: Option<&[u8]>,
        operands: &[Vec<u8>],
    ) -> Result<Vec<u8>> {
        let mut result = match base_value {
            Some(v) => v.to_vec(),
            None => Vec::new(),
        };

        for operand in operands {
            if !result.is_empty() {
                result.push(self.delimiter);
            }
            result.extend_from_slice(operand);
        }

        Ok(result)
    }

    fn partial_merge(
        &self,
        _key: &[u8],
        left: &[u8],
        right: &[u8],
    ) -> Result<Vec<u8>> {
        let mut result = left.to_vec();
        result.push(self.delimiter);
        result.extend_from_slice(right);
        Ok(result)
    }
}
```

## 4. 范围扫描路径

### 4.1 Iterator 设计

ForSt-RS 的 Iterator 需要合并来自多个数据源的有序结果：

```rust
/// 合并迭代器：多路归并来自 MemTable + ImmutableMemTables + SST 文件的数据
pub struct MergingIterator {
    children: Vec<Box<dyn KvIterator>>,
    current: Option<(usize, Vec<u8>, ValueEntry)>,  // (child_idx, key, entry)
    direction: Direction,
    read_seq: u64,
    merge_operator: Option<Arc<dyn MergeOperator>>,
}

pub trait KvIterator: Send {
    fn valid(&self) -> bool;
    fn key(&self) -> &[u8];
    fn value(&self) -> &ValueEntry;
    fn next(&mut self) -> Result<()>;
    fn seek(&mut self, target: &[u8]) -> Result<()>;
}

impl MergingIterator {
    pub fn new(
        active_memtable: Box<dyn KvIterator>,
        imm_iters: Vec<Box<dyn KvIterator>>,
        l0_iters: Vec<Box<dyn KvIterator>>,
        level_iters: Vec<Box<dyn KvIterator>>,  // L1-Ln 各一个
        read_seq: u64,
        merge_operator: Option<Arc<dyn MergeOperator>>,
    ) -> Self {
        let mut children = Vec::new();
        children.push(active_memtable);
        children.extend(imm_iters);
        children.extend(l0_iters);
        children.extend(level_iters);

        let mut iter = MergingIterator {
            children,
            current: None,
            direction: Direction::Forward,
            read_seq,
            merge_operator,
        };
        iter.find_smallest();
        iter
    }

    /// 找到所有子迭代器中最小的 key
    fn find_smallest(&mut self) {
        self.current = None;
        for (i, child) in self.children.iter().enumerate() {
            if child.valid() {
                match &self.current {
                    None => self.current = Some((i, child.key().to_vec(), child.value().clone())),
                    Some((_, ref cur_key, _)) => {
                        if child.key() < cur_key.as_slice() {
                            self.current = Some((i, child.key().to_vec(), child.value().clone()));
                        } else if child.key() == cur_key.as_slice() {
                            // 同一 key 多版本，取 sequence 最大的（最新版本）
                            // 跳过其他子迭代器中的同 key 记录
                        }
                    }
                }
            }
        }
    }
}
```

### 4.2 前缀扫描（Prefix Scan）

前缀扫描是 Delta Join 场景的关键操作（文档 1.17），ForSt-RS 预留了优化接口：

```rust
/// 前缀扫描：返回所有以 prefix 开头的 key-value 对
/// 比范围扫描更高效：利用 PrefixExtractor + Bloom Filter 跳过无关 SST
pub fn prefix_scan(
    &self,
    cf: &ColumnFamilyHandle,
    prefix: &[u8],
) -> Result<Box<dyn KvIterator>> {
    let cf_data = self.get_cf(cf)?;
    let snapshot = cf_data.snapshot_view();
    let read_seq = self.sequence_number.load(Ordering::Acquire);

    // 计算前缀的 upper bound（prefix 最后一个字节 +1，用于界定范围）
    let upper_bound = prefix_upper_bound(prefix);

    // MemTable 迭代器（prefix scan）
    let mem_iter = snapshot.active_memtable.prefix_scan(prefix, read_seq)?;
    let imm_iters: Vec<_> = snapshot.imm_list.iter()
        .map(|imm| imm.prefix_scan(prefix, read_seq))
        .collect::<Result<Vec<_>>>()?;

    // SST 文件迭代器（利用 prefix bloom filter 过滤）
    let version = snapshot.current_version();
    let sst_iters = self.create_sst_iters_for_prefix(
        version, prefix, upper_bound.as_deref(), read_seq
    )?;

    Ok(Box::new(MergingIterator::new(
        mem_iter, imm_iters, sst_iters.l0, sst_iters.levels,
        read_seq, cf_data.options.merge_operator.clone(),
    )))
}
```

## 5. SnapshotView 与 MVCC

### 5.1 SnapshotView（类 SuperVersion）

ForSt/RocksDB 使用 SuperVersion 概念来实现读取的快照隔离。ForSt-RS 使用类似的 SnapshotView：

```rust
/// SnapshotView: 某一时刻的引擎只读视图
/// 持有 MemTable、ImmutableMemTable 和 Version 的引用计数
/// 读取期间即使发生 Flush/Compaction，SnapshotView 仍然有效
pub struct SnapshotView {
    /// 当前活跃 MemTable 的引用
    pub active_memtable: Arc<dyn MemTableReader>,
    /// 不可变 MemTable 列表（从旧到新）
    pub imm_list: Vec<Arc<dyn ImmutableMemTable>>,
    /// 当前 Version（SST 文件布局）
    pub version: Arc<Version>,
    /// 快照序列号
    pub sequence: u64,
}

/// ColumnFamily 数据持有者
pub struct ColumnFamilyData {
    /// 活跃 MemTable（可写）
    active_memtable: Arc<RwLock<Box<dyn MemTable>>>,
    /// 不可变 MemTable 队列
    imm_list: Arc<RwLock<Vec<Arc<dyn ImmutableMemTable>>>>,
    /// 当前 SnapshotView 的缓存（ArcSwap 无锁切换）
    cached_snapshot_view: ArcSwap<SnapshotView>,
}

impl ColumnFamilyData {
    /// 获取 SnapshotView — 无锁操作
    pub fn snapshot_view(&self) -> Arc<SnapshotView> {
        self.cached_snapshot_view.load_full()
    }

    /// MemTable 切换或 Flush/Compaction 后更新 SnapshotView
    fn update_snapshot_view(&self) {
        let new_view = Arc::new(SnapshotView {
            active_memtable: self.active_memtable.read().as_reader(),
            imm_list: self.imm_list.read().clone(),
            version: self.version_set.current(),
            sequence: self.sequence_number.load(Ordering::Acquire),
        });
        self.cached_snapshot_view.store(new_view);
    }
}
```

### 5.2 MVCC 可见性规则

ForSt-RS 使用 sequence number 实现 MVCC：

```
可见性规则:
  entry.sequence <= reader.read_seq  →  可见
  entry.sequence > reader.read_seq   →  不可见

多版本排序规则（同一 key 内）:
  (key ASC, sequence DESC)
  → 对于同一 key，sequence 大的排在前面
  → 读取时取第一个 sequence <= read_seq 的条目
```

| 场景 | 行为 |
|------|------|
| 读取在写入之前 | read_seq < write_seq → 写入对读取不可见 |
| 读取在写入之后 | read_seq >= write_seq → 写入对读取可见 |
| Compaction 中 | Compaction 保留 read_seq 范围内所有版本 |
| Checkpoint 快照 | 快照 read_seq 之后的写入不影响快照 |

## 7. 性能分析

### 7.1 读路径延迟对比

| 操作 | ForSt (JNI) | ForSt-RS (FFM) | 改进 |
|------|------------|----------------|------|
| 单次 get (Cache Hit) | ~57ns JNI + ~1us lookup = ~1.1us | ~23ns FFM + ~1us lookup = ~1.0us | ~10% |
| 单次 get (Cache Miss) | ~57ns JNI + ~10us IO = ~10.1us | ~23ns FFM + ~10us IO = ~10.0us | ~1% |
| batch_get 100 keys (Cache Hit) | 100 × 1.1us = ~110us | 1 × 23ns + 100 × ~0.8us = ~80us | ~27% |
| batch_get 100 keys (Cache Miss) | 100 × 10.1us = ~1010us | 1 × 23ns + 共享 Block 加载 = ~300us | ~70% |

**batch_get 的核心优势**：
- 共享 Block 加载：多个 key 可能落在同一 DataBlock，只需加载一次
- 批量 Bloom Filter：同一 SST 文件的 Bloom Filter 只加载一次
- 减少跨语言调用：100 个 key 只需 1 次 FFM 调用（vs 100 次 JNI）

### 7.2 写路径延迟对比

| 操作 | ForSt (JNI) | ForSt-RS (FFM) | 改进 |
|------|------------|----------------|------|
| 单次 put | ~57ns JNI + ~0.5us insert = ~0.6us | ~23ns FFM + ~0.3us insert = ~0.3us | ~50% |
| WriteBatch 100 entries | 100 × 0.6us = ~60us | 1 × 23ns + batch_insert = ~15us | ~75% |

**WriteBatch 的核心优势**：
- 一次序列号分配（vs 100 次 atomic 操作）
- 批量 Arrow RecordBatch 构建（连续内存布局）
- 单次 MemTable 阈值检查（vs 100 次）

## 9. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| batch_get 中某个 key 触发 Merge 合并，拖慢整批返回 | P99 延迟飙升 | 限制 Merge 深度（max_merge_operands），Compaction 提前合并 |
| 大量 L0 文件导致 batch_get 扫描多个 SST | 读放大 | Compaction 优先级：L0 文件数超阈值时提升 Compaction 优先级 |
| Arrow RecordBatch 构建开销（内存分配 + 列填充） | 小批量场景退化 | 小批量（<10 keys）走单条路径，避免 Arrow 构建开销 |
| SnapshotView 生命周期过长导致旧 Version 无法释放 | 内存泄漏 | 读操作完成后立即释放 SnapshotView 的 Arc 引用 |
| 前缀扫描（prefix_scan）在无 PrefixExtractor 时退化为全扫描 | 性能灾难 | Delta Join 场景强制配置 PrefixExtractor |
